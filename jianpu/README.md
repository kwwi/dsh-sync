# 手写简谱 → 五线谱 (PDF + MIDI)

从两张手写简谱照片还原乐谱，输出五线谱 PDF 与 MIDI。

## 成品文件

| 文件 | 说明 |
|---|---|
| `out/score.pdf` | 五线谱，3 页，钢琴大谱表（高音谱表 + 低音谱表），含调号、拍号、标题、速度、终止小节线 |
| `out/score.mid` | MIDI，2 轨，59 小节，♩=84 |
| `out/score.musicxml` | MusicXML，可在 MuseScore / Sibelius / Dorico 里继续编辑 |
| `out/jianpu_transcription.txt` | 识别出的简谱原文，便于逐小节与原照片核对 |
| `out/preprocessed/sbd1_clean.png` | 清理后的第 1 页（去光影、去倾斜、去噪） |
| `out/preprocessed/sbd1_ink-only.png` | 仅保留笔迹的二值图 |
| `out/preprocessed/sbd2_clean.png` | 清理后的第 2 页 |
| `out/preprocessed/sbd2_ink-only.png` | 仅保留笔迹的二值图 |

## 乐谱信息

* 标题：**Chapter 1 - What Is**（手写体，5/5 次取样一致）
* 调号：**1 = bB**（降 B 大调，五线谱上两个降号）
* 拍号：**4/4**
* 结构：第 1 页 8 行、第 2 页 8 行；每行 2～6 小节，共 **59 小节**
* 织体：上行是主调（旋律），下行是和弦低音（每小节一个长音）

第 1 页第 2～5 行是同一音型的四次陈述：`0 6 1 6 0 6 1 6` 与 `0 5 7 5 0 5 7 5`
交替，低音为 6 5 4 5（G–F–降E–F，即 i–VII–VI–VII，是一段小调色彩的进行，
虽然记谱写作 1 = bB）。第 6 行之后进入正式主题，音符时值变长并出现延长线。

## 处理流程

### 1. 图像清理 (`clean_export.py`)

照片是横格笔记本纸，有斜向阴影（拍照者的手影）、螺旋装订、桌面背景。

1. **颜色分离**：笔迹是深蓝，横格线是浅蓝，纸是暖白。
   用 `亮度 − 0.55 × 蓝色度` 做打分，压掉纸张和暖色阴影，突出墨迹。
2. **光照拉平**：除以大半径高斯模糊得到的背景，使纸面均匀变白，
   消除斜向阴影造成的明暗差。
3. **去倾斜**：旋转不同角度并计算水平投影方差，取方差最大者（第 1 页 −2.00°）。
4. **自适应二值化**：逐像素与周围纸面对比（`pixel < local_paper − Δ`），
   而不是用全局阈值——因为阴影让纸面亮度从 196 掉到 150，
   固定阈值会在暗处把纸纹当墨迹、在亮处丢掉细笔画。
5. **去横格线**：横格线在整页宽度上近似连续，而音符笔画和简谱的下加线都短。
   用宽窗口内的"水平暗像素密度"判定横格线像素并剔除。

### 2. 分行与小节切分 (`lines.py`, `segment2.py`, `permeasure.py`)

行墨迹在垂直方向上的投影被阴影拖出一条缓慢漂移的趋势线；
减去该趋势后，每个乐句变成一个尖锐的峰，取峰间谷底作为切分点。

第 1 页检出 9 条带（第 1 条是标题行），第 2 页 8 条 —— 与图像模型独立数出的
"每页 8 行"完全吻合。

### 3. 识别 (`transcribe.py`, `permeasure.py`, `simpleread.py`)

这里用了两轮互相独立的识别，再由程序投票：

* **第一轮**：把每行切成 3 个互相重叠的窗口，每窗取样 4 次，
  要求模型输出 `[音级|八度|时值]` 三元组，共 196 次调用。
* **第二轮**（主力）：按小节切成放大约 3 倍的独立裁片，
  用**分解式提问**——"有哪些数字"、"每个数字的点在上面还是下面"、
  "每个数字下面有几条下加线"、"最后一个数字后面写的是什么"、
  "低音行是什么"——一次只问一件事。分开问远比一次性打包成三元组可靠。

投票规则：音级、八度、时值分别取众数；某小节的第一轮与第二轮读数若互相印证则采纳。
最终 **45/52 小节**采用第二轮读数，其余 7 小节沿用第一轮投票。

### 4. 音乐性规整 (`assemble2.py`, `regularize.py`)

* **小节时值必须正好 4 拍**。不是按比例缩放，而是**在简谱惯用音型里求解**：
  一小节内常见"先快后慢"，于是穷举 `前 k 个十六分 + 其余八分`、
  `前 k 个八分 + 其余四分` 等模板，取**恰好填满 4 拍且与画出的下加线差异最小**的那个。
* **重复音型时值统一**：同一行内音符数相同的各小节取多数时值。
* **八度按音型统一**：同一串数字每次出现应带同样的八度点。
* **非常规时值拆分**：如 2.5 拍会写成 `二分音符 + 八分音符` 的延音连接，
  保证五线谱上每个音符都是标准时值。

### 5. 出谱 (`jianpu2xml.py`, `render.py`)

简谱音级 → 音高：`1 = bB`，`1..7` 映射到降 B 大调音阶
（1=Bb 2=C 3=D 4=Eb 5=F 6=G 7=A）。
无点的中音区 1 = Bb4（MIDI 70），下加一点低一个八度。
低音行统一加一个下加点，落在低音谱表（G3 / F3 / Eb3）。

用 music21 生成 MusicXML 与 MIDI；再用 Verovio 排版成 SVG，
经 svglib 落到 A4 PDF 上。

> 注意：SVG 内容的坐标原点不是页面原点（内容可能从负 x 开始）。
> 早期版本按 `(0,0)` 摆放会把标题左边缘裁掉（"Chapter" 变成 "ter"）。
> 现在按图形自身的包围盒缩放并平移。

## 关键坑：纸上的「点状横格线」

第一版转换出来后**旋律完全不对**。排查后找到两个真正的根因：

### 1. 纸张的点状横格线污染了识别

这种笔记本的横格线不是实线，而是**由约 2×3 像素的小点排成的点线**，点距约 5 像素。
一行乐谱上有 300～900 个这样的小点，密密麻麻夹在手写数字中间。

视觉模型把这些小点当成了**简谱的八度点**，甚至当成了数字本身——
我曾经拿到过「数字 8、数字 9」这种简谱里根本不存在的读数。

用连通域分析按面积过滤（只保留高度 ≥8 像素、面积 ≥45 像素的笔画），
一行 900 个连通域里只剩约 50 个是真正的笔迹。**去掉这些点之后，
同一个提问立刻给出稳定、自洽的答案。**

### 2. 小节数数错，导致所有裁片错位

第一版用「乐句均分」来猜每行有几个小节，几行猜错了：

| 行 | 第一版假设 | 实际 |
|---|---|---|
| p2 第 1 行 | 3 | **2** |
| p2 第 3 行 | 2 | **3** |
| p2 第 4 行 | 3 | **4** |

小节数一错，每个裁片都跨在两个小节之间，识别出来的音符自然全错。

低音行每小节恰好一个音，所以**低音行的数字个数 = 小节数**。
用这个办法重新数，16 行里有 13 行 5/5 次取样一致。

### 3. 模型会漏掉小节开头的休止符

确认过原谱开头是 `06 16 06 16`（8 个数字），
但模型读每行**第一个**小节时总是少读一个数字，读成 `6 1 6 0 6 1 6`；
而同一行后面完全重复的小节却读得完整。
所以加了「前导休止符补全」：若 A 的读数等于 B 的读数加一个前导休止符，
就用完整的形式。

注意**只补旋律、不补低音**——这首曲子的旋律会重复，但每小节下面的低音是变的
（例如 6 5 4 5 对应同一句旋律的两次陈述），把低音一起合并就会错。

## 识别可信度与已知不确定处

* **数字（音级）**：前四行（第 2～5 行，就是 `06 16` / `05 75` 那一段）
  现在与确认过的开头完全一致，可信度高。
* **后面的主题段（第 1 页第 6 行以后、第 2 页）**：明显比第一版好，
  但仍是全曲最不可靠的部分。数字笔画连写、时值变长、又夹着延长线，
  模型在这几行的取样分歧最大。
* **节奏（下加线条数）**：模型经常把一条下加线报成两条。
  这里不直接采信，而是**在简谱惯用音型里求解**：穷举
  「前 k 个十六分 + 其余八分」等模板，取恰好填满 4 拍、
  且与报出的下加线差异最小的那个。59 个小节全部落在 4 拍上。
* **八度点**：见下。
* **速度**：原谱没有速度标记，MIDI 的 ♩=84 是**我设的默认值**。
* **反复记号**：原谱最后一小节有「X 6 (遍)」的反复提示，当前按一遍直通输出。

### 关于八度点

旋律数字上下的小圆点决定八度，这是本次最难判断的一项。
用几何方法验证过：把一行里所有小连通域找出来，
它们的水平间距几乎恒定为 4～5 像素、并排成横贯整页的直线——
**这是纸张的印刷点线，不是手写的八度点**。
所以旋律**统一记在中音区（不加八度点）**，低音行低一个八度。

## 一个重要的现实限制

**送给我的图片已经被压缩过。** 附件元数据显示原始拍摄是 3024×4032，
实际到手的是 1536×2048，**长宽各缩了一半**。换算下来：

* 一个小节约 353 像素宽，一个手写数字只有约 **44×30 像素**
* 若用原始分辨率，一个数字会有约 **88×60 像素**

对这个连写的手写体来说，30 像素高的数字处在识别的临界线上。
**如果能提供原始分辨率的照片（或直接把照片裁成每页/每行再发），
后面几行主题段的识别准确率会有明显提升。**

另外建议：拍摄时让纸面尽量平整、光线均匀，避开手影；
如果能只发乐谱区域（不含螺旋装订和桌面），效果会更好。

## 如何重新生成

```bash
cd jianpu
.venv/bin/pip install music21 verovio svglib reportlab pypdfium2

python3 clean_export.py      # 清理图像
python3 lines.py --t 132     # 切行
python3 transcribe.py        # 第一轮识别（需 DeepSeek API key）
python3 permeasure.py        # 逐小节识别
python3 simpleread.py        # 第二轮分解式识别
python3 assemble2.py         # 投票 + 音乐性规整
.venv/bin/python build_score.py   # 出 MusicXML / MIDI / PDF
python3 export_jianpu.py     # 导出简谱文本
```

识别脚本通过 `~/.dsh/.credentials.yaml` 里的 `DEEPSEEK_API_KEY`
调用 `deepseek-flash` 的视觉接口。
