## 背景

## 理由

### 1. 排盘引擎一次做对，避免返工

十神、地势、藏干均为**确定性规则**，与 LLM 无关。首期在引擎层就算全，数据结构稳定后 v1.0 只需开 UI 开关，无需重构 API。

### 2. MVP 用户价值聚焦「起名结果」

小程序首期核心验证点是：**用户是否认可「命格 → 典籍出处 → 好名字」链路**。父母用户更关心备选名与通俗建议，而非「枭比食」等专业术语。完整命盘留作 v1.0 付费差异化或专业用户吸引力。

### 3. 降低 LLM 幻觉风险

MVP 阶段 LLM 输入为结构化 JSON（五行统计、日主、月令、刑冲标记、调候提示），输出限制为**通俗结论 + 名字解读**。不让 LLM 自由发挥十神推理，减少与引擎结果不一致的风险。

### 4. 控制首期交付周期

预估 MVP 周期 6～8 周（1 后端 + 1 小程序 + 0.5 算法）。若 MVP 同时要求完整专业解读 + 平仄 + 全语料，周期延长至 12 周以上，不利于快速验证。

## MVP 报告展示结构（用户可见）

```
1. 基本信息（性别、出生地、公历/农历、八字四柱）
2. 【命格简析】（3～5 句通俗结论：五行、喜用神方向）
3. 【取名建议】（优先五行、风格说明）
4. 【备选名字】×3
   - 完整姓名
   - 典籍出处 + 白话释义
   - 五行属性
   - 拼音
```

**折叠区（灰色提示「完整命盘即将上线」）**：不展示或展示占位。
